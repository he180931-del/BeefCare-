Invitation and membership commands (`POST .../invitations`, `.../resend`, `.../cancel`, `PUT .../members/{id}`) now require the `Idempotency-Key` header and run through `IdempotencyCommandService.execute(farmId, VIEW_FARM_INFORMATION, ...)` (Owner-only permission, rechecked on replay); accept is naturally idempotent and takes no key. Messages: MSG-FE03-02/03/04/08/09/20 and MSG-FE01-xx have English and Vietnamese text in `domain_messages*.properties`.

The legacy generated CRUD routes (`/api/farm-invitations`, `/api/farm-memberships`, `/api/app-users`) stay closed: anonymous 401, signed-in 403 (`BrowserSessionFlowIT`). Their generated tests (`FarmInvitationResourceIT`, `FarmMembershipResourceIT`) and the JHipster `AccountResourceIT` were retired (they needed Docker/Testcontainers and asserted an open, JWT-era API without CSRF); the equivalent behaviour is covered by `BrowserSessionFlowIT`, and the shared factory moved to `EntityFactories.farmMembership`.

Endpoints: `GET /api/farms/{farmId}/members`; `GET/POST /api/farms/{farmId}/invitations`; `POST /api/farms/{farmId}/invitations/{invitationId}/resend|cancel`; `PUT /api/farms/{farmId}/members/{membershipId}`; authenticated `GET/POST /api/invitations/accept`.

`20261028000110_membership_lifecycle.xml` adds invitation token metadata and member effective-date/reason/version fields. `20261028000120_durable_mail_dispatch.xml` adds link nonces and the retryable email job table. Invitation/account tokens are never returned in API DTOs or persisted in raw form. Platform access is storage-backed and rechecked on every protected command; `IdempotencyCommandService.executePlatform(...)` requires a named role before both replay lookup and execution.

# FE20 Hỗ trợ khách hàng – implementation plan

## Goal

Hoàn thiện UC-FE20-01 đến UC-FE20-13 theo `docs/requirements/specs/FE-20-ho-tro-khach-hang.md`, nối frontend với backend và xác minh dữ liệu được lưu/đọc từ database thật.

## Workstreams

1. Audit spec/API/DTO/entity/resource/frontend types and record all missing fields, visibility rules, state transitions, idempotency and version checks.
2. Complete backend contract and security: owner ticket flows, CS processing, internal requests, PM/SA completion, public/internal visibility, atomic history/notification/outbox writes, unavailable-CS requeue and DB integration coverage.
3. Implement backend adapters for owner and platform-support frontend APIs; map DTOs/errors/versions/idempotency without falling back to demo stores in backend mode.
4. Complete owner and CS/PM/SA screens for SCR-64..69, including create/list/detail/reply/ack/reopen/claim/handover/status/classification/notes/resolution/close/internal requests and visibility restrictions.
5. Run real PostgreSQL-backed integration/smoke flows, frontend unit/typecheck/build, backend compile/tests, and update OpenAPI/evidence.

## Completion gates

- All 13 use cases have a reachable UI and backend route in backend mode.
- No support operation silently reads/writes mock/localStorage when backend mode is active.
- Owner never receives CS-only notes/internal requests; PM/SA never receives ticket conversation.
- Version/idempotency and transaction rollback are covered by tests and DB read-back evidence.
- Focused tests, typecheck/build, and real-DB verification are recorded before completion.

## Evidence rules

- Unit tests assert pure public return values and errors.
- Integration tests assert the public service/controller result plus a fresh persistence/session readback where state matters.
- System/E2E coverage reuses these fixtures/contracts at WBS12/WBS13; it must not duplicate helper-only tests or be reported as a cross-language automated journey without one.
- Earlier RED reports caused by missing implementation are historical evidence only; the final focused gates are GREEN: backend unit 36/36, H2 auth 53/53, PostgreSQL 28/28, OpenAPI 5/5, Node 9/9, and Vitest 200/200.
- WBS5 is N/A/closed: authoritative D34/K12 explicitly says password reset/change audit is out of scope; no action names or audit tests are invented in this matrix.
- WBS6 initial RED was intentional against the pre-implementation state (missing remembered deadline and expiry enforcement); after Coding's implementation, `RememberedSessionAbsoluteExpiryIT` is 5/5 GREEN and is included in the final H2 auth gate.
- WBS7 contract: reset token is captured once in component memory, removed with email from browser history before interaction, submitted successfully from the captured value, and never persisted in localStorage/sessionStorage/cookie; reload of the scrubbed URL cannot recover it.
- WBS7 header scope: reset SPA routes plus reset validate/finish responses receive `Referrer-Policy: no-referrer` and `Cache-Control: no-store`; unrelated routes retain the current policy and CSP/CSRF behavior. The FE-01 spec does not currently state these hardening headers; they are the WBS7 security contract.
